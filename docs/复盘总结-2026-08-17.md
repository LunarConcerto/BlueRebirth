## 2. SDK（new_sdk.dll）关键结构

- 导出：`login=0x3A850`(→真实现 `0x19060`)、`loginDemo=0x3A7F0`、`initSDK=0x3A780`、`tickLoop=0x3AA40`、`closeCustomWebView=0x3B9D0`、`openCustomWebView=0x3B960`、`getSuperNotice=0x3CD00`、`setSimulationInfo=0x3CE20`。ImageBase `0x10000000`。
- 登录单例全局 `[0x1005EF54]`；回调对象 `[0x1005EF50]`，派发走 `vtable+0x18`（`__thiscall`，`(const char* name, const std::string& result)`）。
- **initSDK 回调的真实签名是 `void __stdcall(int eventId, const char* payload)`**（C# `OnCallBack` 的 P/Invoke 桥）。这是本次最重要的发现：直接 `originalSdkCallback(2, json)` 就能派发登录事件，绕开 SDK 的 C++ 字符串。
- SDK 用**自定义 C++ string**（非 MSVC std::string）：SSO 缓冲在 `+0x10`、size 在 `+0x20`、capacity 在 `+0x24`（约 0x2C 字节）。这是崩溃根因之一（见 §5）。

- `BabelTimeSDK.Login()`(0x2D1870) 与 `new_sdk.login`(0x3A850) **实际都没被调用**——游戏进入 LoginPage 后 SDK 内部直接弹公告 WebView（event 29）。

  （`protocolStatus:"2"` 标记用户协议已同意，`isZYXSDK` 为真所以跳过 isAdult 等字段。）

## 5. 踩坑复盘（本次两个崩溃 + 一个方向错误）

1. **`0xC0000409`（栈越界）**：最初直接调 SDK `vtable+0x18` 派发并传 payload 的 `std::string`。SDK 用自定义字符串布局（VS2010/msvcr100），payload 用 MSVC2019 的 `std::string`，跨 ABI 边界布局不一致 → 栈被写坏。**教训：跨模块传 C++ 对象（尤其 string）前必须确认 ABI**。改用 `originalSdkCallback(2, const char*)` 解决。
2. **重定位踩坑**：`new_sdk.login` 首指令 `mov eax,[0x1005ef54]` 的绝对地址操作数会被 loader 重定位（模块常加载到非首选基址如 `0x20290000`）。`memcmp` 比对文件字节必然失败。**教训：对含绝对地址的指令，只校验不重定位的 opcode 字节（如 `0xA1`）**，其余靠模块 SHA-256 兜底。
3. **方向错误**：上一阶段把「进入游戏」卡点误判为 `NetSocket.Connect` 建 socket 失败（对象图半初始化）。实际上用户侧表现是「点进入 → getPlatformUserInfo → 弹网络错误」，根因在 SDK 接口层（AppleReview 恒 -1，见 §7）。**教训：先看用户可见表现（弹窗）定位，别一头扎进深层反汇编。**

## 6. 服务器响应类型约定（重要）

Lua 端一律 `result.errornu ~= "0"`（**字符串**比较），所以**由 Lua 解析**的端点 `errornu` 必须是 `"0"`（带引号）：

- `/phone/serverlist/`、`/phone/loginrole/`、`/gethash`、`/phone/platform/getPlatformUserInfo/` → `"errornu":"0"`。
- 而 SDK 内部 asInt 解析的端点（getPlData、switch、applereview）各有各的类型，见 Program.cs 注释。

新增端点：`/phone/platform/getPlatformUserInfo/` 返回 `{"errornu":"0","data":{"isFastUser":1,"idcardStatus":1,"isAdult":1,"OnNoRealnameLogin":0}}`，让 `_CheckRealName(true)` 走 `isFastUser==1` → `OnSDKEnterGame`。

## 7. 「网络不可用」根因（AppleReview 恒 -1）

反汇编 `SetReview`(0x2D4060) 确认：它只写 `HasReceiveReviewResult=1`(0x71)，**从不写 AppleReview(0x74)/AndroidReview(0x78)**；且 `set_AppleReview`(0x2D50B0) 全 `.text` 零调用。故 `AppleReview` 恒为 `REVIEW_NO_GOT(-1)`。

`LoginLogic.CheckUpdate` 里 `AppleReview==IS_REVIEW(1)` 分支永远不成立，走 `CheckNetState()/HasUpdate` 分支，最终弹「网络不可用」（`\231\189\145\231\187\156\228\184\141\229\143\175\231\148\168`，loginlogic.lua:93/147）。

**修复**：payload 直接补写 `sdkStatic+0x74=1`、`+0x78=0`。效果：`CheckUpdate → _HasUpdate(false) → GetSDKHash() → gethash`，不再弹网络错误。

> 备注：08-16 总结里「applereview=1 使 AppleReview==IS_REVIEW」这条是**未经验证的假设**，本轮证明是错的。

## 8. WebView 隐藏

- event 29 打开的是**公告 supernotice**（URL 带 `/phone/supernotice/`），不是扫码。
- `closeCustomWebView`(0x3B9D0) 只派发 "close" 事件（解锁 UI），**不销毁原生 CEF 窗口**。
- 真正白屏是 `#32770` 空标题对话框 + `Chrome_WidgetWin_0`。用 `EnumWindows` 枚举本进程窗口，`ShowWindow(SW_HIDE)` 隐藏 `#32770`(空标题) 与 `Chrome_*`。
- 为避免 SDK 反复 reopen（open/close 死循环 + UI 反复加锁），close 只在**第一次** open 时调度一次，之后只周期隐藏窗口。
