## 2. 游戏登录 TCP 协议（NetSocket）

- **帧格式**：`[4字节大端长度][1字节 type][可选 16字节 MD5 hash][payload]`。首条登录 type=1(带 hash)、后续 type=0。`HEAD_LEN=5`、`HASH_LEN=16`、`MD5_KEY="e768f298"`。
- **信封**：C2S = `TRequest{Method=1, Args=2, CallbackHandler=3, Token=4}`；S2C = `TResponse{Err=1, ErrMsg=2, Method=3, Ret=4, CallbackHandler=5, Time=6, Token=7, Seq=8, IsResponse=9}`。
- **响应类型**（protobuftypemanager.lua 映射 + dump.cs 字段）：
  - `player.Login` → `TRetLogin{Ret=1, FeignRoleId=2, ErrCode=3}`（客户端显式检查 `ErrCode==0`，必须写出）
  - `player.GetUserList` → `TRetGetUsers{ArrUser=1}`（空列表 → 客户端走 CreateUser）
  - `player.CreateUser` → `TUserInfo{Uid=1, Uname=2, Level=3, Class=4}`
  - `user.UserLogin` → `TRetUserLogin{Ret=1, BanMsg=2, BanTime=3}`（`Ret=="ok"` 才继续）
  - `user.GetUserInfo` → `TRetGetUserInfo{Uid=1, Uname=2, ..., Class=7, ..., Level=10, ...}`
- **登录 Lua 流程**（`userservice.lua`）：`_ReceiveLogin → GetUserList → CreateUser → UserLogin → GetUserInfo → LoginOk`。全程 `waitRecv=true`（`baseservice.lua`），但串行化靠 Lua 的 token 机制（`socket_net.lua`），**C# 层 `LuaSend` 强制 `waitRecv=false` 不阻塞**。
- **关键：`Data.userData` 由 `user.UpdateUserInfo` 推送设置**（`_UpdateUserInfo`），`user.GetUserInfo` 的响应**不**设 `Data.userData`（`_ReceiveUserGetUserInfoFunc` 只发 LoginOk）。所以服务器必须在登录后主动推 `user.UpdateUserInfo`。

## 3. 关键 C# RVAs / 偏移（GameAssembly.dll）

```
NetSocket   Connect=0x2A4990  Send=0x2A5A00  ReceivedPacket=0x2A53C0  SendCore=0x2A5760
            字段: currState=0x8  socket=0x10  receiveBuffer=0x14  needHash=0x2C
NetCore     字段: conn=0x8  serializer=0xC  netService=0x10  waitMethod=0x18  lastSentMsg=0x20
NetLogic    LuaSend=0x2A2F10(强制 waitRecv=false)  Send=0x2A3250
NetService  Send=0x2A44C0
NetCore     Send=0x2A1E70  Dispatch=0x2A1670(响应匹配: waitMethod!=Empty 且 method==waitMethod)
StageMgr    Goto=0x1ECD80  get_Ins=0x1ED5F0
GameSceneManager  ChangeScene=0x5431C0  (字段: curPath=0x10, curSceneInfo=0x14)
EStageType  eNone=0  eStageLogin=1  eStageMain=2  eStageSimpleBattle=3  eStageLaunch=5
```

- **`NetSocket.Send` 里 `currState!=2` 才返回 false**；`[ebp+8]=this, [ebp+0xc]=msg`。
- **IL2CPP x86 数组布局**：`klass=0, monitor=4, bounds=8, max_length=0xC, data=0x10`（**与 string 不同**：string 的 length 在 +8、chars 在 +0xC）。这是之前钩子读错长度的根因。
- **IL2CPP x86 调用约定**：`this` 在栈上（[ebp+8]），非 ECX。带 `[BlackListAttribute]` 的 Lua 桥接方法（如 `LuaSend`）前面有隐藏 methodInfo 参数。
- **cctor 守卫截断坑**：很多 IL2CPP 方法开头是 `55 8B EC [51] 80 3D <disp32> 00`（`cmp byte [cctor],0` 共 7 字节，占 bytes 4-10）。`InstallStrArgHook` 的 `stolenLen=10` 会把这 7 字节切断（少 `00`），导致跳回时的 `E9` 被吞成 `cmp` 立即数 → 崩溃。**带 cctor 守卫的方法必须 `stolenLen=11`**。

## 4. 服务器侧修复（`BlueOath.Server` / `BlueOath.Protocol`）

1. **`UserInfoCodec` 字段 key 修复**：`TUserInfo` 之前把字段号当原始 varint 写，改为 `WriteKey(field<<3|wire)`。
2. **`user.UserLogin`/`user.GetUserInfo` 处理器**：方法名补 `user.` 前缀，`Ret="ok"`，新增 `EncodeRetGetUserInfo`（Uid=1/Uname=2/Class=7/Level=10）。
3. **stderr 管道阻塞修复**：game-login 日志从 `Console.Error` 改写到 `game-login.log` 文件（`File.AppendAllText`），避免测试脚本只在 kill 后读 stderr 导致管道写满阻塞。
4. **新增 `/phone/getuserextra/` 端点**（event 1008，LoginOk 后调用）。
5. **新增 `user.UpdateUserInfo` 推送**：`user.GetUserInfo` 响应后，主动推一帧 `TResponse{Method="user.UpdateUserInfo", Ret=TRetGetUserInfo, CallbackHandler=0, IsResponse=0}`（push），让客户端 `_UpdateUserInfo` 设 `Data.userData`（`BuildUpdateUserInfoPush`）。
6. **测试**：修 `GameLoginIntegrationTest` 改用 NetSocket 帧；14/14 集成测试 PASS。
