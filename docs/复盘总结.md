## 五、关键逆向知识库（保留的精华）

### 5.1 游戏登录 TCP 协议（NetSocket 帧）

- 帧格式：`[4 字节大端长度][1 字节 type][可选 16 字节 MD5 hash][payload]`。首条登录 type=1（带 hash）、后续 type=0。`HEAD_LEN=5`、`HASH_LEN=16`、`MD5_KEY="e768f298"`。
- 信封（protobuf）：C2S=`TRequest{Method=1, Args=2, CallbackHandler=3, Token=4}`；S2C=`TResponse{Err=1, ErrMsg=2, Method=3, Ret=4, CallbackHandler=5, Time=6, Token=7, Seq=8, IsResponse=9}`。
- 登录 5 步：`player.Login → player.GetUserList → player.CreateUser → user.UserLogin → user.GetUserInfo`。`player.GetUserList` 返回空 `ArrUser` → 客户端走 `CreateUser`。
- `player.Login` 响应 `TRetLogin{Ret=1, FeignRoleId=2, ErrCode=3}`，客户端显式检查 `ErrCode==0`（必须写出，即使为 0）。
- 服务端 push（`CallbackHandler=0`/`IsResponse=0`）：`user.UpdateUserInfo` 携带完整 `TGetUserInfoRet`（客户端 `UserService._UpdateUserInfo` 据此设 `Data.userData`）。**`user.GetUserInfo` 的响应本身不设 `Data.userData`，必须靠这个 push**。
- `TGetUserInfoRet` 关键字段：Uid=1(uint64)、Uname=2(string)、Class=7、Level=10、Diamond=12、Gold=13、Supply=14(体力)、**SecretaryId=23(uint32，看板英雄实例 ID，当前用 1)**。
- 引导绕过：`MainStage:StageEnter` 里 `lastPage==eStageLogin` 时先发 `PushAllNotice`（会读 build/bath 数据，缺则 `pairs(nil)` 崩溃）再 `OpenGroupPage({"HomePage","firstLogin"})`。payload `ForceMainStage` 直调 C# `StageMgr.Goto(2)` 绕过 Lua 引导拦截。

### 5.2 玩家数据推送（`BuildSyncPushes`，登录后随 `user.UpdateUserInfo` 一起推）

| 方法 | Ret 结构 | 当前值 | 说明 |
| --- | --- | --- | --- |
| `build.BuildsInfo` | `TBuildsInfoRet{BuildedList=1, BuildingList=2, WaitingList=3, BuildedLast=4}`，元素 `TFormula{EndTime=1(int64), Project=2, HeroId=3}` | `BuildingList=[{EndTime:0}]` | `EndTime` 必须显式写出（0 也写），否则客户端读到 nil 会崩 |
| `bathroom.BathroomInfo` | `TBathroomInfo{HeroList=1, IsAllAuto=2}`，元素 `TBathHeroInfo{HeroId=1, Pos=2, IsAuto=3, StartTime=4, ...}` | `HeroList=[{HeroId:0, StartTime:0}]` | `HeroId`/`StartTime` 必须显式写出 |
| `hero.UpdateHeroBagData` | `THeroInfo{HeroInfo=1(THeroGrid), HeroBagSize=2, HeroNum=3}`，元素 `THeroGrid{HeroId=1, TemplateId=2, Equips=3, Lvl=4, ..., PSkill=13, ..., Fashioning=22}` | `HeroInfo=[{HeroId:1, TemplateId:10210511, Lvl:1, Fashioning:1021051}]` | `HeroId` 必须与 `SecretaryId` 一致 |

### 5.3 配置数据库解码

- `StreamingAssets/config/config_*.db` 是 SQLite，表 `DBObject(id, indexid, jsonbytes)`；`jsonbytes` 每个字节与 `0x55` 异或后是 JSON：`decoded[i] = encoded[i] XOR 0x55`（可逆）。
- 解码后的 JSON 就是配置表行（如 `config_parameter`、`config_ship_main`、`config_fashion`、`config_ship_show`、`config_ship_model`）。

### 5.4 默认秘书（看板角色）配置链

`config_parameter[17].value = 10210511`（TemplateId）→ `config_ship_main[10210511].ship_info_id = 1021051` → `config_ship_info[1021051].sf_id = 1021051` → `config_fashion[1021051]`（`is_default=1`）→ `config_ship_show[1021051]`（`model_id="u_cl_oakland"`，看板模型）→ `config_ship_model["u_cl_oakland"].standard_normal = 102105101`（dressID）。

### 5.5 IL2CPP 调用约定（x86）

- **实例方法**：`this` 在栈上第一参数 `[esp+4]`（即 `[ebp+8]`），**不是 ECX**。
- **静态方法**：`(MethodInfo*, args...)`，`MethodInfo*` 是第一参数。
- **字符串**：`klass@0x0 / monitor@0x4 / length@0x8 / chars@0xC`（UTF-16）。
- **数组**：`max_length@0xC`、`data@0x10`。
- **hook trampoline**：`pushad` 后，实例方法第一个参数在 `[esp+36]`、第二个在 `[esp+40]`；静态方法第一个参数在 `[esp+36]`。
- 字符串字面量可能走 relocation，直接在 `.text` 里按地址搜不到；定位字符串消费者要运行时 hook。

### 5.6 hook stolenLen 规则（关键，踩过坑）

- 5 字节跳转（`E9+rel32`）覆盖 `addr..addr+4`，所以 `stolenLen >= 5` 且必须落在完整指令边界，否则回跳落在跳转指令中间 → 垃圾代码 → 崩溃。
- IL2CPP 函数常见 prologue：
  - `55 8B EC 80 3D <disp32> 00`（static-field guard 在 bytes 3-9，7 字节）→ **stolenLen=10**。
  - `55 8B EC 51 80 3D <disp32> 00`（多了 `push ecx`）→ **stolenLen=11**。
- 回跳用 `jmp rel32`，别用 `mov eax,target; jmp eax`（破坏 EAX）。
- 反汇编索引用 `pefile.get_memory_mapped_image()`（RVA 索引，不是文件偏移），别再用 `RVA-0xC00` 去索引。

### 5.11 服务器响应类型约定（关键坑）

- **Lua 端解析的端点**（`errornu` 用字符串 `"0"` 比较）：`/phone/serverlist/`、`/phone/loginrole/`、`/gethash`、`/phone/platform/getPlatformUserInfo/` → `"errornu":"0"`。

## 六、方法论教训（重做必读）

1. **运行时 hook 读内存 > 静态反查 IL2CPP 元数据结构**（fieldOffsets 运行时才初始化、metadataUsage 编码对不上、images 表结构不明）。
2. **每加一个 hook 可能扰动时序**，导致冻结点漂移；诊断 hook 和功能 patch 要拆开、可开关。
3. **先看用户可见表现（弹窗/日志）定位，再一头扎进深层反汇编**——很多次卡点是 SDK 接口层的类型/格式问题，不是深层逻辑。
4. **跨模块传 C++ 对象（尤其 string）前必须确认 ABI**——SDK 用自定义 string 布局（SSO@+0x10、size@+0x20、capacity@+0x24），直接传 MSVC std::string 会栈破坏崩溃。
5. **崩溃 dump 是定位 hook bug 的金标准**：minidump ExceptionStream 拿异常码/地址，ThreadInfoList 的 ThreadContext 拿 EBP/EIP/ESP，沿 EBP 链回溯定位抛点。
6. **「满足自然流程」可能是无底洞**（场景加载是黑盒），关键要回答「谁在什么时候触发 XX 加载」这个根本问题，而不是盲目补 null guard。
7. **PowerShell 写含中文/转义引号的文件要 UTF-8**，改 `.cs` 里的转义引号用精确字符串替换，别用 `-replace` 碰非匹配文本。
