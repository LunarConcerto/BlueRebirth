### 4.5 本轮方法论沉淀（重要）

1. **Lua nil 比较陷阱**：`nil ~= 0` 在 Lua 中为**真**。服务端字段为 0 时若不编码，客户端读到 nil，会导致 `if v.Replace ~= 0` 这类判断走错分支（返回 nil 而非跳过）。**凡客户端会读取做比较/拼接/算术的整型字段，必须无条件编码（即使值为 0）**。

2. **空消息编码陷阱**：protobuf 重复字段若编码 `length=0` 的空消息（如 `0x12 0x00`），会被解码成**单个空元素**而非空数组，导致 `element.field` 为 nil。要表示「无数据」应**不编码该字段**，而非编码空消息。

3. **堆损坏排查**：`0xc0000374` 是堆损坏（`ntdll.dll`），非 Lua 逻辑错误。查 Windows 事件日志（`Get-WinEvent Application`）拿异常码，可快速定位是原生内存问题。本项目的 `ForceMainStage` 从 payload 后台线程调 `StageMgr.Goto` 是根因，延迟只是缓解。

4. **船娘详情的数据依赖**：GirlShowPage 需要 HeroGrid 的 `Exp`(5)、`Lvl`(4)、`CurHp`(9)、`TemplateId`(2)、PSkill 的 `PSkillId`(1)/`PSkillExp`(2)/`Level`(3)/`Replace`(4)。这些字段缺一则属性/技能/经验条显示崩溃。

### 4.8 新手引导画面闪现修复（2026-08-19）

**现象**：每次进入游戏，登录后短暂闪现新手引导画面（GuidePage），随后被 StartAnimationPage 覆盖。

**根因**：`guide.GuideInfo` 推送的**时序错误**。引导系统初始化发生在 `user.UserLogin` 响应阶段：

```
user.UserLogin 响应 → LuaEvent.LoginOk → LoginStage:_LoginOk
                                        → guideHub:onLoginOK()
                                          → guideManager:init()   ← 读 GUIDE_DONE_STAGES（此时为空）
                                          → LOGIN_END 触发第一个 stage(id=10000) → GuidePage
```

原实现把 `guide.GuideInfo` 放在 `user.GetUserInfo` 之后的 `BuildSyncPushesAsync` 里，比 `guideManager:init()` 晚，`GUIDE_DONE_STAGES` 读不到，所有 stage 被误判未完成。

**修复**：把 `guide.GuideInfo` 推送**提前到 `user.UserLogin` 应答之前**（与 `user.UpdateUserInfo` 同位置）。

**关键知识点**：

| 项 | 说明 |
|----|------|
| 引导触发链路 | `LoginOk` → `LoginStage:_LoginOk` → `guideHub:onLoginOK()` → `guideManager:init()` + `LOGIN_END` |
| `GUIDE_DONE_STAGES` | 引导进度，value 是 `Serialize` 序列化的表（**字符串 key**）`{["10000"]=1,...}` |
| `GUIDE_DOING_STAGE` | 进行中 stage，空字符串表示无 |
| 引导 stage | `guideStageConfig.lua` 共 29 个顶层 stage，第一个 id=10000 `triggerType=LOGIN_END` |
| **推送时序原则** | **依赖客户端初始化时机的推送，必须在触发该初始化的请求应答前发送** |

- `PlayerDataCodec.cs`：新增 `GuideSetting`/`GuideInfo` record + `Encode`（`FuncList`/`PlotList`/`Event` 占位避免 `#nil`/`pairs(nil)` 崩溃）。
- `GameLoginMessageHandler.cs`：`BuildGuideInfoPush`（`DoneGuideStages` 29 个 stage id + `BuildDoneGuideStages`）。
- `GameLoginSession.cs`：`user.UserLogin` 分支里 `user.UpdateUserInfo` 之后推 `guide.GuideInfo`。

### 5.1 游戏登录 TCP 协议（NetSocket 帧）

- 帧格式：`[4 字节大端长度][1 字节 type][可选 16 字节 MD5 hash][payload]`。首条登录 type=1（带 hash）、后续 type=0。`HEAD_LEN=5`、`HASH_LEN=16`、`MD5_KEY="e768f298"`。
- 信封（protobuf）：C2S=`TRequest{Method=1, Args=2, CallbackHandler=3, Token=4}`；S2C=`TResponse{Err=1, ErrMsg=2, Method=3, Ret=4, CallbackHandler=5, Time=6, Token=7, Seq=8, IsResponse=9}`。
- 登录 5 步：`player.Login → player.GetUserList → player.CreateUser → user.UserLogin → user.GetUserInfo`。`player.GetUserList` 返回空 `ArrUser` → 客户端走 `CreateUser`。
- `player.Login` 响应 `TRetLogin{Ret=1, FeignRoleId=2, ErrCode=3}`，客户端显式检查 `ErrCode==0`（必须写出，即使为 0）。
- 服务端 push（`CallbackHandler=0`/`IsResponse=0`）：`user.UpdateUserInfo` 携带完整 `TGetUserInfoRet`（客户端 `UserService._UpdateUserInfo` 据此设 `Data.userData`）。**`user.GetUserInfo` 的响应本身不设 `Data.userData`，必须靠这个 push**。注意：该 push 在 `user.UserLogin` 应答**之前**发出，否则 `LoginOk` 事件触发时 `m_TypeNumMap` 尚未初始化会崩。
- `TGetUserInfoRet` 关键字段：Uid=1(uint64)、Uname=2(string)、Class=7、Level=10、Exp=11、CreateTime=22、**SecretaryId=23(uint32，看板英雄实例 ID)**、BuyGoldNum=26、BuyGoldTime=27、BuySupplyNum=28、BuySupplyTime=29、HeadShow=44、NewTaskStage=46（新手活动进度，设 7 跳过引导）、ServerId=56。

### 5.5 IL2CPP 调用约定（x86）

- **实例方法**：`this` 在栈上第一参数 `[esp+4]`（即 `[ebp+8]`），**不是 ECX**。
- **静态方法**：`(MethodInfo*, args...)`，`MethodInfo*` 是第一参数。
- **字符串**：`klass@0x0 / monitor@0x4 / length@0x8 / chars@0xC`（UTF-16）。
- **数组**：`max_length@0xC`、`data@0x10`。
- **hook trampoline**：`pushad` 后，实例方法第一个参数在 `[esp+36]`、第二个在 `[esp+40]`；静态方法第一个参数在 `[esp+36]`。
- 字符串字面量可能走 relocation，直接在 `.text` 里按地址搜不到；定位字符串消费者要运行时 hook。

### 5.6 hook stolenLen 规则（关键，踩过坑）

- 5 字节跳转（`E9+rel32`）覆盖 `addr..addr+4`，所以 `stolenLen >= 5` 且必须落在完整指令边界，否则回跳落在跳转指令中间 → 垃圾代码 → 崩溃。
- IL2CPP 函数常见 prologue：
  - `55 8B EC 80 3D <disp32> 00`（static-field guard 在 bytes 3-9，7 字节）→ **stolenLen=10**。
  - `55 8B EC 51 80 3D <disp32> 00`（多了 `push ecx`）→ **stolenLen=11**。
- 回跳用 `jmp rel32`，别用 `mov eax,target; jmp eax`（破坏 EAX）。
- 反汇编索引用 `pefile.get_memory_mapped_image()`（RVA 索引，不是文件偏移），别再用 `RVA-0xC00` 去索引。

### 5.12 日服 Lua 全量反编译（1526 文件，2026-08-18 完成）

**结论**：日服 Lua 字节码就是**标准 Lua 5.3.5**（4 字节指令、标准 LUAC_DATA

- `checkHeader`（0x10011d20）：format 校验 `1`、checksize 4 个字段 `4/4/8/8`、LUAC_INT `0x5678`、LUAC_NUM `370.5`。
- `LoadCode`（`LoadFunction` 内 0x1001185c `lea esi,[ecx*4]`）：代码段按 `sizecode*4` 字节读入 = **标准 4 字节指令**。

**产物**：
- `lua_tools/BlueoathLuaJP/` — 1526 个反编译 `.lua`（含 13 个空 stub），可读源码
- `runtime/lua-normalized/` — 归一化 header 后的字节码（unluac 输入）
- `tools/extract-normalize.py` — 正确解包（二进制）+ header 归一化
- `tools/decompile-all.py` — unluac（`java -jar unluac.jar`）批量反编译

**头号教训（走了很长的弯路）**：原 `tools/extract-lua.py` 用
`open(dest,"w",encoding="utf-8",errors="ignore")` **文本模式写二进制字节码**，
把 `0x93` 等非法 UTF-8 字节丢掉、把 LF 转成 CRLF，制造出「可变长指令 + CRLF 转义 +
自定义 LUAC_DATA」的假象，误判为「需要自写 8 字节指令反编译器」，白耗大量时间。
正解：UnityPy 的 `TextAsset.m_Script` 把非法字节存成 surrogate（`0x93`→`\udc93`），
用 `m_Script.encode('utf-8','surrogateescape')` 还原原始字节 + `open("wb")` 二进制写盘。

**header 归一化三步**：`format` `01`→`00`、`sizeof(Instruction)` `08`→`04`、offset 16 插入 `sizeof(lua_Number)=08`。

**意义**：日服 Lua 现在全部可读，比国服（1397）多 129 个文件（crusade / assistfleet /
plotcopymain 等国服没有的玩法），后续 Mod / 还原 / 对照可直接读日服源码，不必再靠国服近似。

## 六、方法论教训（重做必读）

1. **运行时 hook 读内存 > 静态反查 IL2CPP 元数据结构**（fieldOffsets 运行时才初始化、metadataUsage 编码对不上、images 表结构不明）。
2. **每加一个 hook 可能扰动时序**，导致冻结点漂移；诊断 hook 和功能 patch 要拆开、可开关。
3. **先看用户可见表现（弹窗/日志）定位，再一头扎进深层反汇编**——很多次卡点是 SDK 接口层的类型/格式问题，不是深层逻辑。
4. **跨模块传 C++ 对象（尤其 string）前必须确认 ABI**——SDK 用自定义 string 布局（SSO@+0x10、size@+0x20、capacity@+0x24），直接传 MSVC std::string 会栈破坏崩溃。
5. **崩溃 dump 是定位 hook bug 的金标准**：minidump ExceptionStream 拿异常码/地址，ThreadInfoList 的 ThreadContext 拿 EBP/EIP/ESP，沿 EBP 链回溯定位抛点。
6. **「满足自然流程」可能是无底洞**（场景加载是黑盒），关键要回答「谁在什么时候触发 XX 加载」这个根本问题，而不是盲目补 null guard。
7. **PowerShell 写含中文/转义引号的文件要 UTF-8**，改 `.cs` 里的转义引号用精确字符串替换，别用 `-replace` 碰非匹配文本。
8. **二进制数据（字节码、打包文件）绝不能用文本模式写盘**：`open(path,"w",encoding=...)` 会丢非法 UTF-8 字节、做 LF→CRLF 转换，造成「看似自定义编码」的假象。一律 `open("wb")` + `bytes`。这次日服 Lua 反编译绕了一大圈，根因就是 `extract-lua.py` 把字节码当文本写。
9. **服务端整型字段必须无条件编码（即使值为 0）**：Lua 里 `nil ~= 0` 为真、`nil + 0` 报错。客户端只要对某字段做比较/拼接/算术，服务端就必须写出该字段（哪怕 0），否则客户端读到 nil 会走错分支或崩溃。典型：HeroGrid 的 `Exp`/`Mood`/`MarryTime`/`MarryType`、PSkill 的 `Replace`。
10. **protobuf 空消息 ≠ 空数组**：`length=0` 的消息字段会被解码成「单个空元素」而非空数组，导致 `element.field` 为 nil。要表示「无数据」应**不编码该字段**，而非编码空消息（典型：HeroGrid 的 `Equips`）。
11. **报错要追到「谁在每帧调用」**：报错每帧刷屏时，先看 traceback 里的 `CoUpdateBeat`/`LateUpdate`，判断是「页面每帧刷新」还是「CreateSubPart 的虚拟列表每帧重建」，这决定了根因是数据缺失还是布局逻辑。
12. **推送时序 = 客户端初始化时序**：服务器推送若依赖客户端在「某请求应答时」做的初始化，就必须在该请求应答**之前**发出。典型：`user.UpdateUserInfo`（`LoginOk` 时读 `m_TypeNumMap`）与 `guide.GuideInfo`（`LoginOk` → `guideManager:init` 时读 `GUIDE_DONE_STAGES`）都必须在 `user.UserLogin` 应答前推，否则初始化读到空数据。定位这类问题先查「客户端哪个请求的应答触发了初始化」。
